Предметная область:
Сервис доставки еды принимает заказы от клиентов. 
Клиент выбирает блюда из меню и оформляет заказ.
Оператор обрабатывает заказ и передаёт его на кухню. 
Повар готовит блюда, после чего заказ передаётся курьеру. 
Курьер доставляет заказ клиенту. 
Администратор управляет пользователями, меню и выгружает отчёты о продажах.

Таблица ролей:
| Роль | Задачи в системе |
| :--- | :--- |
| Администратор | Все действия оператора, управление пользователями, управление меню, выгрузка отчётов |
| Оператор | Приём и обработка заказов, назначение курьера, связь с клиентом |
| Повар | Просмотр заказов на кухне, отметка о готовности блюд |
| Курьер | Просмотр назначенных заказов, отметка о доставке заказа клиенту |

Бизнес-процесс:
1. Клиент заходит на сайт или звонит в сервис.
2. Оператор принимает заказ и проверяет наличие блюд.
3. Создаётся заказ (статус «Новый»).
4. Оператор передаёт заказ на кухню.
5. Повар начинает готовить (статус «Готовится»).
6. После готовности всех блюд повар меняет статус на «Готов к доставке».
7. Оператор назначает курьера (статус «В пути»).
8. Курьер доставляет заказ и отмечает его как «Доставлен» (или «Отменён»).

Таблица статусов:
| Из статуса | Разрешено перейти в | Условие |
| :--- | :--- | :--- |
| Новый | Готовится, Отменён | «Готовится» — только если все блюда в наличии |
| Готовится | Готов к доставке, Отменён | «Готов к доставке» — только если назначен повар |
| Готов к доставке | В пути, Отменён | «В пути» — только если назначен курьер |
| В пути | Доставлен, Отменён | «Доставлен» — только если курьер подтвердил вручение |
| Доставлен, Отменён | — (конечные статусы) | — |

Пользовательские истории:
US-01: Как оператор, я хочу зарегистрировать нового клиента по номеру телефона, чтобы создать для него заказ на доставку.
Критерии приёмки: 
1.Телефон должен быть уникальным; 
2. Телефон автоматически приводится к формату +7XXXXXXXXXX; 
3.Если телефон уже есть в базе, система предложит выбрать существующего клиента.

US-02: Как повар, я хочу отметить заказ как готовый, чтобы оператор мог назначить на него курьера.
Критерии приёмки:
1.Без подтверждения готовности всех блюд статус не меняется; 
2.После смены статус — «Готов к доставке», время готовности заполнено; 
3.Чужой заказ повар изменить не может.

US-03: Как администратор, я хочу создать нового пользователя с ролью «Курьер», чтобы он мог брать заказы в доставку.
Критерии приёмки:
1.Пароль должен быть не короче 8 символов; 
2.Логин должен быть уникальным; 
3.Роль обязательна для выбора.

US-04: Как оператор, я хочу видеть список всех заказов с фильтром по статусу, чтобы понимать, какие заказы уже готовятся, а какие ждут курьера.
Критерии приёмки:
1.Фильтр работает мгновенно; 
2.Отображаются только заказы с выбранным статусом; 
3.Сброс фильтра возвращает полный список.

US-05: Как оператор, я хочу получать уведомление об ошибке при вводе короткого комментария к заказу,
чтобы не создавать пустые или непонятные заказы.
Критерии приёмки:
1.Комментарий короче 5 символов не принимается; 
2.Выводится понятное сообщение на русском; 
3.Поле ввода подсвечивается красным.

Требования к взаимодействию модулей:
1. Клиент обращается к серверу только через REST API.
2. Сервер является единственным модулем с доступом к базе данных.
3. Правила жизненного цикла (смена статусов заказа) проверяются на сервере, даже если клиент уже проверил их в интерфейсе.
